# 低分辨率像素重构研究

## 当前结论

本记录针对动漫、卡通和插画在 32、48、64 px 下的转换。目标是让有限像素表达清楚的角色和表情，而非尽可能保留每一条原始线稿。

现有结构保真算法和 TEED 线条辅助没有学到像素画的造型取舍。已撤回本轮未发布的强化线条实验；正式转换流水线保持 0.7.0 的行为。本次新增的是候选算法对比工具和研究记录，尚未实现或训练新的神经重构模型。

## 作品参照

以下作品仅用于人工观察，不作为本项目训练数据，也不随仓库重新分发：

- [Ali Dehshiri：Free 8 Pixel Portrait Sprite](https://ali-dehshiri.itch.io/free-8-pixel-portrait-dialog-box)：作者标注每张头像为 32 × 32；公开预览为 128 × 64 的八张头像拼图。
- [RainyViolets：Yuki; Girl with Beret Art Assets](https://rainyvioletz.itch.io/yuki-girl-with-beret-art-assets)：作者区分了 32 × 32 行走角色和 64 × 64 表情头像。这里参考的是表情头像，而非网页缩略图或行走角色的尺寸。

观察这些作品后，对本项目目标作如下判断：

1. **先组织色块，再决定描边。** 头发可由两三组明暗色块表达体积；脸颊、鼻子和下巴可以使用有色阴影或省略局部轮廓。深色线条不是必须覆盖全部边界的约束。
2. **五官需要重新安排。** 眼睛的高光、瞳孔、眼睑以及嘴巴各占少量明确的格子。它们的形状和相对位置比还原源图中的线宽更重要。
3. **不同尺寸需要不同造型。** 32 px 可以省略鼻线、发丝和衣服纹理，并适当调整眼睛或饰品；它不是 64 px 结果的机械缩小版。
4. **干净不等于没有中间色。** 中间色应服务于阴影或有意安排的边缘过渡，不能成为满图的采样碎色。

这些是对参考作品的视觉分析，不是对某种算法质量的量化证明。

## 已核对的方法

| 方法 | 与本需求的关系 | 本轮判断 |
| --- | --- | --- |
| 本项目结构保真、SLIC、TEED | 依据源图区域和边缘进行规则网格映射；TEED 只提供边缘响应 | 继续用于较高分辨率和保真转换；不能作为低像素造型模型的替代品 |
| [Deep Unsupervised Pixelization，2018](https://ttwong12.github.io/papers/pixel/pixel.html) | GridNet、PixelNet、DepixelNet 联合学习像素化与重建，而非仅改变插值核 | 提供学习式像素化的早期路线；本轮未复现其网络 |
| [Make Your Own Sprites，2022](https://orca.cardiff.ac.uk/id/eprint/152816/) | 将 cell-aware 像素化与 aliasing-aware 处理分开，以参考像素画的结构特征控制像素格 | 已进行本地预训练网络实验，见下文；尚不满足接入标准 |
| [SD-πXL，2024](https://github.com/AlexandreBinninger/SD-piXL) | 借助扩散先验，直接优化固定低分辨率网格及离散色板 | 目标形式值得借鉴；作者推荐 24 GB 显存，补充材料报告 RTX 4090 上约 1.5–2.5 小时，不适合作为当前实时预览方案 |

SD-πXL 的耗时来自作者[补充材料](https://igl.ethz.ch/projects/sd-pixl/sd-pixl-generating-low-resolution-quantized-imagery-via-score-distillation-supplemental.pdf)，并非本机测试。上述方法均不能据论文示例直接推断在本项目动漫素材上的表现。

## 神经像素化实测

本轮私有实验使用 *Make Your Own Sprites* 的 I2PNet 与 AliasNet 预训练权重，按作者 Test Pro 的固定四像素 cell 路径运行。合并权重来自 [pamparamm/pixelization-safetensors](https://huggingface.co/pamparamm/pixelization-safetensors)，其模型卡注明裁剪合并自原项目。未训练、微调或使用未加载权重的随机模型。

| 项目 | 实验设置 |
| --- | --- |
| 基线 | Shinkou Pixel 0.7.0；结构保真默认参数；CPU；AI 线条辅助关闭 |
| 输入 | 内置 `public/illustration.png`；用户提供的卡通原图截图（含预览界面），两者单独处理 |
| 目标尺寸 | 长边 64、48、32 px，保持宽高比 |
| 网络输入 | 源图以 bicubic 调整到目标宽高的四倍；RGB / NCHW；归一化到 `[-1, 1]` |
| 网络输出 | I2PNet → AliasNet；恢复字节 RGB，再按四像素 cell 最近邻提取原生目标网格 |
| 色彩对照 | 同时保留原始预测，以及映射到基线同一份色板的结果；后者使用本项目的 Oklab 最近色，无抖动 |
| 后处理 | 不再施加线条保护、边界规整或碎点合并，避免用旧流水线覆盖网络学到的形状 |
| 环境 | 本地 PyTorch 2.10.0 CPU，8 个线程；不是桌面应用中的 ONNX/WebGPU 推理 |
| 权重 SHA-256 | `0946c1e46e3db48018e9eae50a85ae1aab752f129d1126b0ddfbe0e7bdab4494` |

**观察结果：** 深色线稿明显减轻，部分边界能够转为区域色差；但内置插画出现背景偏色、眼部变软和表情变化，32 px 仍然缺少明确的五官组织。使用同一份源图色板能够约束颜色范围，但不能修复网络造成的造型和表情问题。卡通原图也没有普遍达到参考手工作品的清晰程度。

这仅是两张素材上的定性试验，不能据此给出模型整体排名或质量百分比。既没有采用论文展示图作为本项目输出，也没有把私有实验结果包装成已发布功能。

**许可约束：** [原项目许可](https://github.com/WuZongWei6/Pixelization/blob/main/LICENSE.md)限定非商业科研/个人实验，并限制未经书面许可的重新分发。研究代码和权重仅留在被忽略的本地实验目录中，没有加入应用、Git 仓库或安装包。后续正式模型必须具备与应用使用范围相容的许可。

## 后续实现方向

应将低像素处理作为独立的**神经重构**任务。输入除了源图，还应包含目标网格尺寸；模型负责选择色块、决定哪里保留或省略轮廓，并重新组织五官。TEED 可作为可选的弱结构条件，不作为要求模型逐条复制的线稿目标。

建议首先验证具有源图条件约束的像素画风格模型。原图的角色身份、构图、主要配色和表情需要单独验证，不能仅以“看起来像像素画”验收。若依赖扩散模型，应使用像素画训练先验与内容条件，而非无条件生图；生成网格还需要严格约束。源图条件过强会复制不适合小网格的线条，过弱则会改变人物，这是需要实测的权衡。

面向最终桌面预览，更适合评估能直接输出目标网格的小型前馈网络，或在许可明确、质量经过人工筛选的训练样本上蒸馏该能力。模型应覆盖多个目标尺寸，以尺寸条件学习不同的细节预算；不能把同一幅高分辨率网络输出继续缩小，冒充完成了 32 px 的重构训练。

离散色板输出可以采用以下表示。这是候选设计，**当前代码未实现**：令目标网格为 $H\times W$，色板为 $P=\{p_1,\ldots,p_K\}$，预测每格选择各色的 logits：

$$
z=f_\theta(X,H,W,P),\qquad
q_{ijk}=\frac{\exp(z_{ijk}/\tau)}{\sum_{l=1}^{K}\exp(z_{ijl}/\tau)},\qquad
Y_{ij}=p_{\operatorname*{argmax}_k q_{ijk}}.
$$

这里网络预测的是最终色块排列，硬选择保证每格只使用色板中的一种颜色；训练先验和内容约束决定造型质量。该表示本身不会自动产生好的像素画，仍需要有效的训练数据、损失设计与验证。

正式接入的条件：

- 在相同构图、相同原生尺寸下对比 32、48、64 px，兼查 160 px 既有行为。
- 检查眼睛、嘴巴、发饰和表情；允许有意简化，不能通过改变人物身份获得更好观感。
- 检查外轮廓、脸颊及头发分区，不能普遍加粗黑线，也不能普遍擦除五官。
- 单独展示模型原始结果与色板约束结果；原生 PNG 与整数倍最近邻预览同时保留。
- 在多张动漫、卡通、插画上通过人工视觉审查，再报告安装体积、延迟、硬件要求和失败情况。

## 本地对比工具

运行已有正式算法的低分辨率基线：

```powershell
node scripts/compare-low-resolution.mjs
```

比较任意候选模型预先生成的原生 PNG：

```powershell
node scripts/compare-low-resolution.mjs --input public/illustration.png --candidate-dir .cache/my-model --label MyModel --output .cache/my-model-comparison
```

候选目录应包含 `64.png`、`48.png`、`32.png`。宽高必须与输入图按对应长边等比缩小后的尺寸一致；工具拒绝暗中缩放候选，也拒绝含半透明边缘的未完成网格。模型名称由调用者提供，工具不验证模型身份或训练来源。

输出包括基线原生图、候选原始图、使用同一份基线色板的候选图、整数倍最近邻对照图、160 px 参考结果，以及记录输入/候选 SHA-256、完整基线参数和色板的 `manifest.json`。默认输出在忽略的 `.cache` 目录，不下载模型、不执行神经推理、不将图片上传到网络，也不给出冒充审美判断的“质量分数”。
