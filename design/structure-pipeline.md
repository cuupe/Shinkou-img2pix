# v0.2：面向动漫插画的结构保留

## 需求与选择

用户需要类似 Minecraft 逐格搭建的卡通画：轮廓、五官、线条与色块关系保持清晰，而非把高清图片压缩成低分辨率照片。示例截图是已完成的 MC 作品，不能仅凭截图确认制作方式，更不能将其作为原图/结果成对的质量评测数据。

本版选择先做本地、确定性的结构感知像素化，而不直接接入扩散生图。理由是动漫插画通常已有需要忠实保留的轮廓和色块，重绘不是首要目标。AI 可用于以后更复杂图像的线稿、主体分割和语义保护，但模型输出仍需要网格与颜色约束。没有下载神经模型或上传用户图片。

参考资料均为原始项目或论文：

- [PixelOE](https://github.com/KohakuBlueleaf/PixelOE)：对比感知轮廓扩展，在最终缩小前保护细节，不依赖神经网络。
- [Pixelated Image Abstraction with Integrated User Constraints](https://cragl.cs.gmu.edu/pixelate/journal.html)：将特征映射、颜色限制和人工约束共同作为像素抽象问题处理。
- [ControlNet](https://github.com/lllyasviel/ControlNet)：提供边缘、线稿等条件控制，是进一步研究受约束重绘的候选技术；本版没有接入，也没有证据保证它逐像素保真。

现有结构算法是独立实现，受到「缩小前保护结构」这一思路启发，不是 PixelOE 官方移植，也不声称达到论文实现或人工像素画师的水平。

## 实现

1. 先生成目标宽高最多 4 倍的分析图；较小输入不先放大。此步的面积积分用于控制计算量，不直接决定最后每个格子的混合色。
2. 在深色和浅色两个方向检测细线，使用相对两侧的亮度差区分细线与普通区域边界，再利用同色邻域支持降低弱纹理响应。
3. 提取色板时增加受保护细节的权重，使占比小的轮廓颜色不容易被大色块挤掉。
4. 先把分析图量化为颜色区域，再按区域覆盖、格子中心支持、细线保护响应共同决定最终格子的归属。
5. 只合并低对比、无细节保护且周围高度一致的孤立单格；相邻的同色单格线、强高光和透明边界不会被这个清理步骤删除。
6. 结构模式不使用抖动。每格为一个色板颜色，Alpha 为 0 或 255，整数倍导出沿用同一份数据。

「线条保护」控制少数高对比线条占据格子的优先级；「碎点合并」控制对低对比孤立点的容忍度。两者随参数历史撤销/重做。「照片采样」完整保留旧路径。

默认亮度、对比度、饱和度均为 0，以避免在结构比较中人为提高反差。预设缩略图随转换方式更新。

## 证据与局限

17 项单元测试通过，包含 256×128 → 32×16 的细线测试：3 px 深色线在旧路径被平均为浅色，在新路径保持深色连线；浅色反向线也做了验证。另有保护开关、平涂、色数、二值 Alpha、透明图、清理不破坏连续细线与强高光的断言。

10 组 Playwright / Edge 检查通过，页面与控制台无错误，包含参数导致实际像素改变、撤销精确还原、模式切换、四种色板、对比、网格、真实 PNG、1536×1024 与 390×844 布局。未提供 Browser 插件，因此使用 Playwright。

额外生成了一张高清动漫插画作为非用户测试输入。公平比较使用同一张图、96×96、24 色、零色彩调整、关闭旧路径锐化；两张结果均来自真实算法，没有人工修图。观察到新路径的外轮廓、发丝和衣领比旧路径更明显；仍有粗细不均与局部信息丢失，不能将其称为完全保真。一次测试用时旧路径约 25 ms、新路径约 92 ms，此数值仅代表本次测试输入与设备。

没有对应用户原始角色图，因此未验证示例角色的真实转换质量。程序不能从 MC 截图可靠还原未提供的高清原画，也不自动去除截图 UI、水印或背景。

已用 view_image 检查同源比较图、完整工作台、窄屏截图。保留现有深色三栏、字号层级、强调色、图标家族和画布样式；新增转换方式、轮廓控制和必要解释，替换默认示例为插画。无横向溢出，侧栏内容超出时独立滚动。

## 下一步的验收方式

需要一张用户实际要搭建的高清原图，最好是未被视频压缩、没有遮挡与透视的角色图。先对相同输入比较 96 / 128 / 160 / 256 格，并分别检查眼睛高光、嘴角、睫毛、发丝、外轮廓连通性和杂色点；不以简单 PSNR 或「边缘更黑」替代主观结构验收。

如果几何方法仍在关键部位反复失败，再评估本地线稿模型/语义区域模型，并加入用户可标记的重要区域与像素修正。生成式重绘应作为用户允许改变造型时的另一路径。
